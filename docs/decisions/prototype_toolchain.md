# Prototype toolchain decision [DOC]

Decision date: 2026-11-08. Owning task: ST-001, phase P1,
requirements REQ02, REQ03 and REQ09. This is the accepted tooling policy for
the current Python prototype. ST-002 implements and qualifies it; ST-003
automates it. It does not select the production engine stack.

Implementation follow-up, 2026-11-08: the
[setup guide](../getting_started.md) and
[ST-002 qualification](../../reports/ST-002%20bootstrap%20qualification.md)
record installation, cold/repeat checks and refusal results. This decision's
original local-baseline observations below remain historical.

## Selected environment

> Goal: [GL01] - SELECT_A_REPRODUCIBLE_PROTOTYPE_BASELINE
> Dependency: [DP01] - CURRENT_SOURCE_AND_UPSTREAM_TOOL_CONTRACTS
> Requirement: [RQ01] - DISTINGUISH_DECISION_FROM_QUALIFIED_SETUP

Use ordinary, GIL-enabled CPython 3.13 with an initial exact pin of **3.13.18**,
managed by **uv 0.13.7**. Qualify Windows x64 first and record the actual OS
build. Other operating systems and Python minors are not qualified by this
decision. Keep runtime dependencies empty: the current package and tests use
the standard library.

Python 3.13.18 is a source-only maintenance release. uv supplies managed
CPython binaries through python-build-standalone, a distinct distribution
whose build identity must be captured during bootstrap. uv 0.13.6 added
3.13.18; the selected 0.13.7 includes subsequent fixes. This avoids making an
unavailable python.org Windows installer part of the setup plan. These are
upstream availability facts, not a local installation claim [RS01], [RS02],
[RS03], [RS04].

Use **Node.js 24.22.2** and its bundled **npm 11.19.1** for development tools
only. Install the official npm packages **pyright 1.1.414** and
**markdownlint-cli2 0.23.1**, whose declared Markdown engine is
**markdownlint 0.41.1**. The selected Node satisfies the lint CLI's Node >=22
requirement. Pin these versions instead of resolving latest at each run
[RS05], [RS06], [RS07].

At selection, the Python patch and Node/uv versions awaited ST-002
qualification. The original local checks below used Python 3.13.12 and Node 25.8.1.
The Pyright and Markdown CLI pins deliberately retain the previously exercised
versions; this is not a claim that every selected tool is the newest release.

Keep the existing Python minor to avoid combining tool setup with a language
migration. Choose uv for explicit interpreter, environment and lock ownership;
venv plus pip could work, but would need separate interpreter and locking
procedures. Adding Poetry/PDM alongside uv would duplicate that ownership.
Keep unittest because the existing refusal specimens already use it. These
are project choices, not claims that alternatives cannot support the engine.

## Dependency and version authority

> Goal: [GL01] - SELECT_A_REPRODUCIBLE_PROTOTYPE_BASELINE
> Dependency: [DP01] - CURRENT_SOURCE_AND_UPSTREAM_TOOL_CONTRACTS
> Requirement: [RQ02] - LOCK_INPUTS_AND_FAIL_ON_DRIFT

ST-002 must add these artifacts; they are not installed or generated by ST-001:

| Artifact | Authority |
| --- | --- |
| .python-version | Exact CPython pin 3.13.18 |
| pyproject.toml | Python support, uv policy and type-check configuration |
| uv.lock | Committed Python dependency resolution, even when empty |
| .node-version | Exact Node pin 24.22.2 |
| package.json | Private development tools and exact direct npm versions |
| package-lock.json | Committed transitive npm versions and integrity |
| scripts/verify.py | Proposed single, fail-closed verification entry point |

Set requires-python to >=3.13.18,<3.14 and require the exact .python-version
for the reference run. Declare tool.uv.required-version ==0.13.7 and
tool.uv.package = false: run this specimen from its checkout without adding a
wheel/build backend. Keep project dependencies empty; any later Python-only
development tools belong in dependency-groups.dev, not runtime dependencies.
Do not maintain a parallel requirements.txt as another version authority.
These settings are part of the implementation contract, not an existing
manifest [RS08].

Put Pyright and markdownlint-cli2 in npm devDependencies with exact versions
without caret/tilde ranges. Record packageManager npm@11.19.1 and exact
Node/npm engines, and have the verifier enforce versions: metadata alone is
not the guard. Use private = true. npm is already needed for Markdown lint;
using upstream Pyright there avoids a second Python wrapper/download path.

Normal verification uses uv sync --locked and uv run --locked, with managed
Python selection, and npm ci. Reject stale or missing lockfiles; never replace
--locked with --frozen, which skips the freshness check. npm ci checks agreement
with its manifest. Invoke local node_modules tools directly or through npm
scripts; a missing local binary must fail, not trigger an npx download or use
a global executable. Installation and verification are separate operations
[RS09], [RS10].

Create only repository-local .venv and node_modules environments. Bootstrap
may download the selected tool/interpreter artifacts, but must not replace
the user's global Python, Node, uv or npm. Record artifact source, platform,
build identity and available integrity checks. Windows setup must handle paths
with spaces. Do not use personal npm-cache paths as the documented interface.

Version upgrades are explicit changes: update the authoritative pins and
lockfiles together, review resolution changes, run the full required checks
and a fresh-environment qualification, then attach results. Record a
replacement decision if a selected artifact is unavailable. Never silently
substitute an installed version. No production packaging or CI claim follows
from creating these files.

## Required checks and optional tools

> Goal: [GL02] - DEFINE_ONE_REVIEWABLE_VERIFICATION_GATE
> Dependency: [DP02] - EXISTING_SPECIMENS_AND_PLANNING_CHECKER
> Requirement: [RQ03] - FAIL_REQUIRED_CHECKS_WITHOUT_MASKING_ERRORS

Every full verification run must perform all of the following. The entry
point must report each result, propagate failure through its final exit code,
and reject missing tools or zero discovered tests. It may summarize multiple
failures, but cannot print overall success after a failed command.

1. Verify actual interpreter, uv, Node, npm and local checker versions against
   their pins. Require current lockfiles and identify the source revision and
   any working-tree changes. Verification must not update those inputs.
2. Run python -m unittest discover -s tests. Current coverage is 87 runtime
   specimens; legitimate count changes need an explained test change, not a
   permanently hardcoded total.
3. Run python -m unittest discover -s scripts/tests. Current coverage is 19
   planning-checker specimens, including malformed dependency and evidence
   cases. Keep this result separate from the runtime suite.
4. Run python -m spinaltap --json and inspect valid JSON, both refusal guards,
   14 accepted default steps, zero refused default steps, x=0.672, y=-0.336
   and remainder approximately 0.008. Compare floats with tolerances.
5. Run local Pyright on spinaltap, tests and scripts with Python 3.13,
   typeCheckingMode standard and warnings treated as failure. Include all
   future verification scripts. Do not lower diagnostics or add blanket
   exclusions to manufacture a pass [RS11].
6. Run python scripts/check_planning.py. Task phases, requirements,
   dependencies, next-task readiness, local links and pseudo-citations must
   pass. This does not prove the semantic truth of evidence.
7. Run local markdownlint-cli2 with its existing default rules on README.md,
   TODO.md and Markdown under docs, reports and research_notes. Keep rule
   configuration unchanged. Do not suppress errors in new documents.
8. Run git diff --check. Confirm verification did not rewrite source,
   manifests, lockfiles or documentation. Generated environment/cache files
   are excluded from version control, not substituted for check evidence.

Mypy is **replaced by Pyright as the required type gate**. It may be used as
an optional second opinion; it is not installed by default and its absence
does not fail verification. The old eight Mypy IDE diagnostics remain a dated
intake, not an unresolved mandatory command check. Pylance/IDE refresh remains
optional ST-004 work. A green IDE is not a CLI gate.

Ruff/Black formatting, extra Python lint rules, pytest migration, coverage
thresholds, pre-commit, Docker and additional type checkers are deferred.
They add setup or policy beyond the established baseline. Add a tool only
with a scoped need, an exact development pin and acceptance evidence. This
decision requires no third-party runtime dependency or test-runner migration.

The documentation scope preserves the existing .agents and .user_notes
exclusions. CHANGELOG is linted/link-checked but is ordinary historical
Markdown, exempt from pseudo-citations. Root VERIFICATION.md describes Rust
media-deduplication commands and tests absent from this repository; preserve
it as an unclassified imported record and exclude it from 4GINE evidence.
The existing explicit documentation targets do not include that file. Do not
claim repository-wide Markdown coverage beyond those targets.

## Clean-environment qualification required by ST-002

> Goal: [GL03] - MAKE_REPRODUCIBILITY_FALSIFIABLE
> Dependency: [DP03] - IMPLEMENTED_BOOTSTRAP_AND_DECLARED_PINS
> Requirement: [RQ01] - DISTINGUISH_DECISION_FROM_QUALIFIED_SETUP

Use a fresh checkout of the implementation revision on Windows x64, without
.venv, node_modules or the author's global checker executables. Use dedicated
empty download caches and record their locations. Normal network acquisition
is allowed for this first bootstrap; do not infer fully offline installation.
Avoid deleting the user's environments or changing their global tool paths.

1. Obtain the pinned uv and Node/npm distributions through the documented
   bootstrap, verify their identities, then acquire managed CPython 3.13.18.
   Record CPython distribution/build, OS/architecture, uv, Node and npm versions.
2. Recreate .venv and node_modules from the committed inputs using the locked
   operations above. Record checksums for manifests and lockfiles. Confirm
   no resolving upgrade occurred and no runtime dependency was introduced.
3. Run the single verification entry point, recording all required results,
   demo output, test discovery counts, source revision and working-tree state.
4. Repeat sync/install and verification against unchanged inputs. Manifest and
   lockfile checksums must remain unchanged. Matching dependency versions are
   the claim; do not promise byte-identical environments or CPU timings.
5. In disposable copies, make each lockfile stale relative to its manifest;
   both dependency paths must fail rather than regenerate locks. Remove one
   required checker, supply a wrong tool version and force one child command
   to fail. Each case must produce an actionable error and nonzero exit.
6. Confirm that using an unsupported Python minor or free-threaded variant
   fails the reference-version check. Test a checkout path containing spaces.
   Missing network/download artifacts must be reported, not treated as a pass.

Publish the exact command log and failure specimens as ST-002 evidence before
marking that task done. ST-003 then repeats the same contract in CI. Merely
writing the proposed manifests, running against a warm global cache, or
passing today's source tests does not satisfy that clean-environment gate.
